Architecture spine · build substrate

Litmus

A personal week planner with projects attached — one task, seen two ways. This is the contract that keeps those two ways from drifting apart.

27 invariants 3 environments Decided 19 Aug 2026 Versions verified live Status final

00

The one idea

Planning a week and running a project are the same information at two angles. Litmus has one Task. It sits in a Project because that is what it is part of, and the moment it gets a due date it appears on the Week Board on that day, because that is when you intend to do it.

Both surfaces are projections of the same thing. Neither is the source of truth. Every serious risk in this build comes from that one sentence being easy to write and easy to violate — an implementation that treats Week Board and Project Board as two independent screens will drift on status, on progress, and on what day a task belongs to, and it will do so quietly.

So the architecture puts the shared thing in the middle and makes the surfaces depend on it. A core owns the entities and every rule derived from them. Feature modules are projections over that core: they own how work is shown, never what work is. Same shape on both sides of the wire.

What we deliberately did not build

Six months from now the useful question is not what is here — the code will tell you that — but why the obvious thing is missing. These are the four that will look like omissions.

Cut · reopen only with evidence

Offline editing, and with it the whole local-first layer

The PRD asked for offline read and edit, a queue draining on reconnect, and per-field last-write-wins. That is a sync-engine requirement, and it was the most expensive thing in the document by a wide margin. Zero 1.0, Livestore and ElectricSQL were all live candidates and all rejected: for one human editing two devices, per-field conflict resolution resolves essentially no conflicts. The server is authoritative, the UI is optimistic, and the network failing produces an honest error. If offline comes back it is a data-layer replacement, not an increment.

Cut · seam reserved

Real-time push between devices

A change on the desktop does not appear on an open phone within seconds; it appears the moment you pick the phone up. Refetch-on-focus and refetch-on-reconnect cost nothing and cover the case that actually happens. AD-13's single invalidation door is where server-sent events go if the rare case starts to matter.

Evaluated · rejected on coherence

Vercel for the frontend

It was a tie on money. A custom domain costs nothing on AWS either — ACM certificates are free, CloudFront alternate domain names are free, and Route 53's $0.50 hosted zone is optional. Vercel's real advantage was effort and preview deploys, which did not outweigh splitting the system across two infrastructure-as-code surfaces when CDK was chosen precisely to avoid that.

Rejected · design wins

Cognito Hosted UI

Cheapest and most secure by default, and it cannot render the three designed auth frames — a two-pane layout whose brand panel is built from the product's own Task Card. Custom screens call Cognito's SRP flow directly instead. The cost is recorded honestly in AD-21: the refresh token lives in browser storage, so the PRD's "not readable by page scripts" is only partly met.

03

The 27 rules

Each one exists because two people building different parts of Litmus would otherwise answer the same question differently. Grouped by what they protect.

Domain AD-1 – AD-5, AD-22 · six rules

AD-1  The core owns Task and Project; features are projections

Prevents
Week Board and Project Board each growing their own Task model, status transitions and date handling.
Rule
Entities and their derived functions are declared in core/domain and Litmus.Core.Domain. A feature may define view models over them; it may not redefine, extend or shadow them, or implement a transition the core does not expose.

AD-2  Feature modules never depend on one another

Prevents
A cycle that makes either surface impossible to change or delete alone.
Rule
Dependencies flow shell → feature → core only, enforced by Nx tags and one-way .NET project references. A feature needing something from another feature means the thing belongs in the core.

AD-3  Derived values are computed at read time and never persisted

Prevents
A stored counter drifting because one mutation path forgot to update it — after which Progress is wrong permanently, silently, and differently on three screens.
Rule
No aggregate is ever written. Progress, counts and "due this week" are pure functions over the task set in hand. A project's freshness is max(project.updatedAt, max(task.updatedAt)), not a field a child write must remember to bump. Tripwire: revisit past ~2,000 tasks.

AD-4  Due Date is a calendar day, not an instant

Prevents
A task landing on the wrong day column for anyone not on UTC.
Rule
dueDate is a YYYY-MM-DD string, never parsed into a Date. Week membership is string comparison. Time ranges are local HH:mm pairs scoped to that day. Audit timestamps are separately UTC instants and are never used for scheduling.

AD-5  Status and Category have exactly one definition

Prevents
A fourth status value, a hidden one, or a category list that differs by surface.
Rule
ToDo | InProgress | Done, closed, defined in C# and generated into TypeScript. Category is single-valued from a fixed v1 list — Design, Dev, QA, Docs — with no management surface.

AD-22  Task order is deterministic and derived

Prevents
Each surface sorting differently — or one persisting a sortOrder the other neither writes nor respects.
Rule
One comparator in core/domain: time range, then priority, then title. No user ordering and no stored order in v1. Adding manual reordering is a datastore change and an amendment here, not a local decision.
Data AD-6 – AD-8, AD-25, AD-26 · five rules

AD-6  One partition per user; the user id comes only from the token

Prevents
A query that forgets to scope by user, and any endpoint that lets a caller name whose data it wants.
Rule
Single table, partition key USER#{sub}. The sub is read only from the JWT authorizer's claims — never from a body, path or query, in any endpoint, ever. Persistence helpers take it as their first argument so an unscoped query will not compile.

AD-7  Subtasks are embedded in their Task

Prevents
Two modules disagreeing about whether a subtask is an item or a field, and a pair that reads half-updated.
Rule
An ordered list attribute on the task item, written and read in one operation. Never separate items, never separately addressable, no due date.

AD-8  The client generates entity ids

Prevents
Temporary-id reconciliation in optimistic inserts, and a retried create producing two records.
Rule
UUIDv7, minted before the request, used in the optimistic cache entry from birth. The server validates the format and rejects a duplicate, making creates idempotent under retry.

AD-25  Deleting a Project takes its Tasks with it

Prevents
Orphaned tasks whose projectId resolves to nothing, rendered differently by every surface.
Rule
projectId never dangles. Deletion cascades in chunked writes within the user's partition, and the confirmation names the count. A task with no project is valid — that is a Week Board task. A task pointing at a project that does not exist is not.

AD-26  Every stored item declares its type and schema version

Prevents
Three modules each inferring an item's kind from its sort-key prefix slightly differently, and a v2 migration with nothing to migrate against.
Rule
type and schemaVersion as ordinary attributes. Readers branch on type, never on key parsing. Shape changes increment the version and ship with a reader tolerating both, so no deploy needs a migration window.
Contract AD-9 – AD-12 · four rules

AD-9  One Lambda, one Minimal API host, one module per route group

Prevents
Function-per-route sprawl, and per-module divergence in middleware, auth, serialization and errors.
Rule
A single .NET 10 Lambda runs ASP.NET Core Minimal APIs behind an HTTP API proxy route. Each module exposes exactly one MapXxxEndpoints extension. Cross-cutting concerns are configured once in the host. The same host runs under Kestrel locally, so the full API is testable without deploying.

AD-10  The wire contract is generated, never written twice

Prevents
A hand-maintained TypeScript mirror of a C# DTO going quietly stale — the classic split-stack drift.
Rule
The backend emits OpenAPI at build time; TypeScript types are generated from it, committed, and never hand-edited. A hand-written interface duplicating a server type is a defect.

AD-11  One error shape

Prevents
Each module inventing its own envelope, forcing per-surface error handling.
Rule
RFC 9457 Problem Details everywhere, which ASP.NET Core produces natively. The client maps them in core/api alone; features consume a normalized error and never parse responses.

AD-12  The read model is a workspace bootstrap plus lazy detail

Prevents
Each surface fetching its own slice, ending up with two cached copies of one task that can disagree on screen.
Rule
GET /workspace returns every project and a lean task index; both boards are selectors over that one response and search is a client-side filter. Descriptions and subtask bodies load on demand. No feature issues a list query of its own.
Client state AD-13, AD-14, AD-21, AD-23, AD-24 · five rules

AD-13  One query-key factory, one cache entry, one invalidation door

Prevents
Two modules keying the same data differently, so one updates and the other shows stale content.
Rule
All keys come from a single factory. The workspace index is one entry. Every invalidation passes through one exported function — which is also where real-time push is added later without touching feature code.

AD-14  Every mutation is optimistic and goes through the core

Prevents
A drag feeling instant while the identical change from a dropdown blocks on the network.
Rule
Named operations in core/api — setStatus, setDueDate, toggleSubtask — each owning its patch and rollback. Features call these and never the HTTP client, and never write their own optimistic logic.

AD-21  Tokens live in memory; the refresh token is the only persisted credential

Prevents
Each surface inventing its own token storage and refresh timing, and access tokens sitting in localStorage for any script to read.
Rule
Custom screens call Cognito SRP directly. Access and ID tokens stay in memory; refresh runs through one interceptor. Accepted deviation: the refresh token remains in browser storage, so the PRD's "not readable by page scripts" is only partly met. The cookie-BFF alternative was judged disproportionate for one user.

AD-23  One mutation per entity at a time; a stale response never wins

Prevents
A fast user silently losing an edit when a status change and a date change race.
Rule
Mutations for one entity serialize. Endpoints return the complete updated entity, applied only when no later mutation for that id is pending — otherwise discarded, optimistic state standing until the queue drains. Failure rolls back and raises one kind of notice through the shell.

AD-24  Preferences live on the Account; view state lives in the URL

Prevents
One surface persisting to localStorage and another to the Account, so the phone agrees about the theme and disagrees about everything else.
Rule
Anything the PRD says persists is on the Account and syncs. Anything describing what you are currently looking at is a typed URL search param. Browser storage holds exactly one thing — the refresh token.
Surface AD-15, AD-16, AD-20, AD-27 · four rules

AD-15  Colour exists only as a token reference

Prevents
Hard-coded hex a theme switch cannot reach, leaving dark mode broken in whichever surface was built last.
Rule
The 21 tokens are custom properties on :root and [data-theme="dark"]; CSS Modules reference var(--token) only, lint-enforced. A project's colour is stored as a token name, never a hex — the pastels are the one family whose dark values are tints, not inversions. Contrast is verified by an automated test, not by review.

AD-16  Every drag has a non-drag equivalent

Prevents
A status change reachable only by pointer, unusable by keyboard and awkward on touch.
Rule
Drag is an accelerator, never the only path. Anything moving a task between statuses or days is also reachable through a control calling the same core operation. New draggable surfaces inherit this.

AD-20  The browser calls nothing but its own origin and AWS

Prevents
A font link or analytics snippet added on one surface quietly making the product phone home.
Rule
Inter and Phosphor Icons are self-hosted — a Google Fonts link would violate the privacy NFR on every screen. No analytics, telemetry, error-reporting SaaS or embeds. Outbound origins are CloudFront, API Gateway and Cognito.

AD-27  One breakpoint scale, mobile-first, no horizontal scroll

Prevents
Each epic inventing its own breakpoints, so three surfaces switch to mobile at three different widths.
Rule
One scale declared in core/ui; no raw pixel media query in a feature. Authored mobile-first from 390 px. The three designed mobile frames are exact targets; surfaces without one take the shared fallback. Overflow is handled inside the element that owns it.
Operations AD-17 – AD-19 · three rules

AD-17  The near-zero cost envelope

Prevents
One infrastructure choice quietly turning a free personal app into a monthly bill — and each environment making that choice differently.
Rule
See the table below. These are hard prohibitions in all three environments, not guidance.

AD-18  Environments are CDK stages; no environment identity in application code

Prevents
if (env === "prod") branches, and staging behaving differently for reasons nobody can find.
Rule
One account, three stages, resources named litmus-{env}-*. Code reads configuration from environment variables and never names an environment. Production stacks carry termination protection. The same artifact shape is built everywhere; only configuration differs.

AD-19  Branch-to-environment is the only promotion path

Prevents
A local cdk deploy reaching staging or production, and environments nobody can trace to a commit.
Rule
develop → dev, qa → staging, main → production; a merge is the only trigger. GitHub Actions assumes an AWS role via OIDC — no long-lived keys exist anywhere. Path filters build frontend, backend and infra independently.

The two that would break it

A VPC. Put the Lambda in one and you need a NAT gateway at roughly $32/month — more than everything above combined, several times over. DynamoDB, Cognito and S3 are all reachable over public AWS endpoints with IAM, so there is no reason to.

SnapStart. It is free for Java managed runtimes only. For .NET it bills for snapshot caching from a three-hour minimum then per millisecond, accruing around the clock per published version, times three environments. Not enabled — the cold start is accepted instead.

Refusal one · TypeScript 6.0.3, not 7.0.2

TypeScript 7's Go-native compiler went GA on 8 July 2026 and is eight to twelve times faster. It is still the wrong pin today: typescript-eslint closed its TS7 support request as not planned, and ESLint core is blocked behind it. AD-2 and AD-15 are both enforced by ESLint rules — adopting TS7 now would switch off the checks this architecture depends on. Revisit when 7.1 lands the stable API; adopt tsgo as a sidecar type-checker first.

Refusal two · .NET 10, not .NET 11

.NET 10 is LTS with support through November 2028 and has been a Lambda managed runtime since 8 January 2026. .NET 11 is Standard Term Support — two years — still in preview, and does not ship until November 2026.

06

Still open

Nothing here blocks building. Each is either a product question the PRD has not answered, or a deferral with a stated condition for revisiting.

  • Notes, and S3 markdown storage. The whole v2 surface. AD-1 and AD-2 already reserve its shape as a peer projection, so adding it should disturb nothing.
  • Read scaling. AD-12 assumes the working set fits one response, which holds at the PRD's fixture scale of 6 projects and 85 tasks. Past roughly 2,000 tasks the answer is a dueDate index and per-surface queries.
  • Server-side task search. A client filter for now. Doing it properly means a scan or OpenSearch, which the cost envelope forbids.
  • Registration closure. Cognito can disable self-signup or restrict to admin creation. Undecided because the PRD has not decided.
  • Social sign-in. Google and Apple as Cognito identity providers, both resolving to one pool. Not designed in until the PRD confirms it is real.
  • Observability. Structured logs only. No tracing, dashboards or alerting — they cost money and there is no one to page.
  • Auth screens in dark theme. A design gap, not an architecture one. AD-15 means the tokens are already in place whenever the frames get drawn.
  • Data export. AD-12's bootstrap already returns the entire dataset in one call, so export is close to free whenever it is wanted.

Two decisions here override the PRD and need to be reflected back into it: offline editing is cut (FR-8 and the offline-tolerance NFR), and the session-token NFR is only partly met (AD-21).
